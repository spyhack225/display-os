# Native device protocol

The configured origin is fixed at APK build time. All HTTP uses standard Android HTTPS certificate validation with system trust anchors. Redirects, query strings, fragments, encoded paths, traversal, foreign hosts and alternative ports fail closed. No TLS-bypass test flag exists in production code.

| Caller | Method and path | Input | Native handling |
| --- | --- | --- | --- |
| Installer | POST `/device/v1/enroll` | `{ticket,publicKey,signature}` | Sign ticket UTF-8 with native P-256 SHA256withECDSA; convert Java DER to raw `r||s` 64 bytes; base64url without padding. Encrypt `{deviceId,deviceToken}`. |
| Native only | POST `/device/v1/recover/start` | `{deviceId,publicKey}` | No bearer. Accept only exact `DisplayOS recovery\nORIGIN\nDEVICE_ID\nCHALLENGE` and bounded challenge. |
| Native only | POST `/device/v1/recover/verify` | `{deviceId,challenge,signature}` | Sign exact message with native key; raw64 base64url. Match returned device ID, encrypt token. Preserve PIN unless a persisted owner-authorized reset is pending and recovery is unclaimed. Deferred-PIN enrollment requires unclaimed recovery and authenticated unclaimed poll. |
| Renderer through native | GET `/device/v1/poll` | none | Add bearer. Return public state or bounded envelope. Native handles erase and expiry before another home can claim. |
| Renderer through native | GET `/device/v1/local` | none | Recent online owned poll and unchanged bearer required before/after fetch. Server must validate current ownership/epoch. At most 32 KiB JSON; 35-second read budget only here. Accept at most 30 seconds above local one-hour TTL, clamp returned expiry to the earlier server expiry/local one-hour limit; expired data denied. Never persist or ACK. |
| Renderer message port | POST `/device/v1/pairing` | `{}` | Add bearer; receive short-lived possession code and claim URL. Never auto-claim. |
| Renderer message port | POST `/device/v1/confirm` | `{phrase}` | Require native dialog, deliberate PIN action and matching latest phrase. Add bearer. |
| Renderer message port | POST `/device/v1/ack` | `{revision,nonce}` | Require current live snapshot, matching receipt and foreground focused visible WebView. Renderer supplies its post-animation-frame ACK. |
| Native erase or scoped port | POST `/device/v1/erase` | `{}` | Only latest owner-authorized erase state. Wipe, rotate, encrypt token; renderer gets `{state:"unclaimed"}` only. |
| Renderer through native | GET `/device/v1/media/MEDIA_ID` | none | Exact safe ID approved by current unexpired snapshot, bounded JPEG/PNG only. Native bearer; encrypted private cache. |
| Renderer | GET `/screen`, `/product/*` | none | Native fetch without bearer. Inject bundled adapter as first external script; enforce native CSP. |

Tokens and factory credentials do not enter HTML, JavaScript, sessionStorage, QR, logs or URLs. Only short-lived claim codes are shown to the family. Unit public-key export and installer ticket responses stay in protected installer storage.

## Fresh factory preparation

The debug-only receiver consumes fixed app-private `files/preparation.json` with exactly `{ticket:string,deviceId:string}`. Optional `ownerPin:string` retains the legacy manual path; null, empty, non-string and unknown fields fail closed. The host script never asks for a PIN. The unit key is generated natively and never replaced by preparation. A stored PIN or completed enrollment forbids headless preparation; a pending identity can retry without a PIN only with its saved fresh/deferred marker and matching ID. Enrollment persists that marker and ID before its HTTP request so lost responses recover with the same Keystore proof. A server-authenticated poll must be `unclaimed` without a snapshot before the credential is committed. Claimed, confirm, erase or unreadable state is not treated as fresh. This additional GET uses the real existing poll endpoint, not a new backend API.

The customer chooses a PIN in the physical native confirmation dialog after QR/manual pairing and matching home words. Existing PINs verify rather than change. Preparation and ordinary recovery cannot reset them. Only the existing deliberate household reset clears a PIN; its persisted marker also handles a lost erase response. Native confirmation is still required and no renderer command sets a PIN.

New screen PINs require exactly six ASCII digits. Verification and legacy manual preparation retain six-digit and 8 to 12 digit support, without advertising legacy formats to the family. Invalid format keeps the same dialog open. Cancel settles the bridge with status 499; stale/expired claim returns 410, duplicate/inactive claim 409. These are native adapter statuses, not new backend endpoints. The human confirmation request times out after 115 seconds; other port requests retain 30 seconds. Expired queued packets are removed before late bootstrap. Native reserves a queue slot for the dialog and releases it on every finish path.

The dialog binds phrase, server expiry, native client, port and generation. It waits at most 90 seconds, shortened to leave 15 seconds before server expiry. Current claim is rechecked before PIN processing, after the KDF immediately before fresh vault commit, after processing, and before confirmation HTTP. Fresh PIN candidate storage replaces live configuration only after successful encrypted persistence. Worker authorization reads only volatile native lifecycle fields, never WebView/UI methods. Foreground UI navigation checks stay on the main thread. Published native state has a nonblocking volatile getter so claim validation does not wait on the PIN KDF. The server still decides whether the claim is valid. No unsafe timing or TLS bypass exists.

## Ephemeral local content

`/device/v1/local` is an exact same-origin GET with no query or request body. Other methods, variants, encoded paths, traversal and foreign origins do not receive credentials. Native interception selects `client.local()` before the generic poll branch. It does not call poll, change delivered state, save any response, acknowledge, recover credentials or use offline cache. A live online `owned` poll no older than 60 seconds is a native precondition, including homes without a current snapshot. The same token and owned state must still hold after fetch and validation; the server's authenticated current ownership/epoch check remains authoritative. Cached/offline polls do not qualify. Non-200 responses retain status but return only `{}` to the renderer.

Wire schema is `{cityLabel?:string,weather?:[{date,label,high,low,condition}],nearby?:[{title,when}]}`. Native normalizes missing arrays to empty and bounds weather to seven rows, nearby to three, strings to 80 characters, dates to YYYY-MM-DD and temperatures to finite numbers from -100 to 100. Unknown top-level or row fields, address/coordinate/token/key fields, markup/control characters and non-JSON success responses are rejected. Only these normalized fields reach JavaScript. The server must avoid addresses or secrets inside allowed strings as well; the client does not claim semantic address detection. No home address, geocode coordinates, provider raw response or provider key belongs in this wire schema.

The native read timeout is fixed at 35000 ms for authenticated local GET only; all other routes and connection setup retain 8000 ms. The package-local overload cannot accept larger budgets or apply the longer budget to another method/path. There is no renderer timeout argument or TLS relaxation. The renderer uses a fixed 45000 ms budget for local information and owner weather/nearby previews, retaining 12000 ms for other requests. Provider dispatch, billing approval and post-network epoch/location-source-version rechecks remain backend responsibilities.

## Message channel

`WebView.postWebMessage` transfers a port only to the exact configured target origin and only after loading `/screen`. Native commands are bound to that WebView generation. Replacement, reload, reset, expiry and preparation restart close old ports and fence queued commands. There are at most eight outstanding commands and sixty commands per minute; payloads are at most 8192 characters. Native body fields are checked again, not trusted because the wrapper checked them.

The first bundled script intercepts `window.DisplayOSUI` assignment and wraps its real XHR helper. GET keeps XHR so `shouldInterceptRequest` can authenticate it. POST uses the scoped port because that callback cannot read POST bodies. Direct unwrapped POSTs are rejected; there is no general JavaScript interface.

Native bootstrap is **not** a same-origin browser-window message. Chromium's Android [AwContents implementation](https://chromium.googlesource.com/chromium/src/+/main/android_webview/java/src/org/chromium/android_webview/AwContents.java) passes null as the source origin when posting to the main frame. The adapter requires a trusted message, null source, opaque `"null"` or empty origin, exact bootstrap tag and exactly one port. Same-origin window messages and synthetic MessageEvents are rejected. Native delivery still supplies an exact target origin, never `*`. This implementation-specific bootstrap must be verified on the actual Android WebView version. The Node test simulates its expected event shape; it does not prove Android delivery.

Android documents [WebView messaging and target origins](https://developer.android.com/reference/android/webkit/WebView#postWebMessage(android.webkit.WebMessage,%20android.net.Uri)). Port messages do not carry a new browser-origin assertion for each command. Native confines the port to its current top-level `/screen`, blocks frames/navigation, closes it on generation changes, and accepts only the device protocol. A compromised same-origin renderer remains a trusted-client compromise; the protocol cannot attest pixels or defend an already compromised Android OS.

## Persistence and lifecycle

The native unit key is never imported from a desktop and is never erased by a household reset. Device-token and content records use separate Android Keystore AES-GCM storage with record-name authenticated context. Recovery proof signs only native-constructed challenges; no renderer signing command exists. A server-authenticated owned poll can reenable content after a denial marker, but offline data cannot.

Expiry hides the WebView and clears content when the app can execute, including on resume and cold start. While Android has suspended or killed the app, physical deletion cannot run. Encrypted expired records must fail the startup gate before rendering. Flash wear leveling and backups outside the stated app boundary are not claimed secure erasure. FullBackup and normal app backup are disabled.

Native ACK is a delivery/render receipt, not a screenshot, human-read confirmation or trusted-display attestation. No Android runtime, boot, lock-task, USB, TLS, Keystore or message-port hardware test was run here. The [Android Keystore documentation](https://developer.android.com/privacy-and-security/keystore) distinguishes nonexportability from hardware backing; this app reports the local `KeyInfo` result to the installer but makes no hardware-attestation claim.

# DisplayOS implementation contract

The customer product runs alongside the unchanged pilot on the existing HTTPS origin. `/home` and `/screen` are the customer surfaces. `/setup` and `/display` lead there; the pilot remains under `/pilot/setup` and `/pilot/display`. No pilot credentials, objects or encryption keys are migrated.

## Chosen architecture

Candidate B provides the smallest authority boundary for household content: one registry for account identity and device assignments, one actor for each home. Candidate A separates units better at large scale but requires a distributed write for every delivery. The registry is a bounded pilot bottleneck, not an unlimited-scale claim. Passkeys replace candidate B's unconfigured third-party identity provider. Reviewed WebAuthn verification runs on the service; biometric or PIN consent runs on the phone.

`ProductRegistry` and `HouseholdState` are new SQLite-backed Durable Object classes. Record values are separately AES-GCM encrypted with key-specific authenticated context. Each actor serializes commands and commits records through storage transactions. No success response precedes the durable write. Cross-actor screen changes use a registry-owned, epoch-fenced pending operation with resumable home attach/detach. Existing `PilotState` remains untouched.

## Shared implementation interfaces

Parent owns `cloud/src/product/{registry,household,store,common}.js`, Worker dispatch/configuration and factory scripts. Delegates own only their assigned modules and tests.

`common.js` exports `HttpError`, `reject(status,message)`, `json(value,status=200,headers={})`, `random(bytes=32)` returning base64url, `digest(string)` returning SHA-256 base64url, `readJson(request,maxBytes=65536)`, `bearer(request)`, `text(value,max)` and `exact(value,allowedKeys)`.

`RecordStore(storage,key,namespace)` provides asynchronous `get(key)`, `put(key,value)`, `delete(key)`, `list(prefix,limit=200)` returning a Map, and `transaction(callback)` calling callback with a transactional RecordStore. Use async operations inside that callback. Caller serializes with `ctx.blockConcurrencyWhile`. Do not hold a transaction open across another actor or network call.

Context passed to registry delegates:

```js
{
  store, origin, env, now: () => Date.now(),
  authenticate(request): Promise<{accountId,sessionId,csrf,verifiedAt}>,
  requireBrowser(request): Promise<principal>, // exact Origin + session + CSRF for POST
  homeCall(homeId, principal, command, input): Promise<object>,
  deviceHome(deviceId): Promise<assignment>,
  rate(bucket,limit,windowMs): Promise<void>
}
```

`identity.js` exports `identityRoute(request,context)` returning Response or null. Owns `/auth/*` and `/api/v1/me`, identity records prefixed `account:`, `credential:`, `challenge:`, `session:`, `recovery:`. Export `authenticate(request,context)`, `requireBrowser(request,context)`. Cookie `__Host-displayos`, Secure HttpOnly SameSite=Lax Path=/; 12-hour session, fresh verification required for account deletion/recovery/member administration. POST exact Origin and `X-DisplayOS-CSRF`, except challenge-bound registration/authentication completion, which still requires exact Origin and a transient HttpOnly challenge cookie. Registration options takes `{name}`. Registration verify takes the library response directly. Authentication options takes `{}`; verify takes library response. Responses `{account:{name},csrf}`. `/api/v1/me` returns same plus `{signedIn:true}` or 401. Account creation never trusts an arbitrary supplied account ID. Recovery returns one-use codes only at deliberate creation, stores hashes, rotates all sessions on use. Add passkey is authenticated; anonymous registration may not overwrite existing accounts. Identity deletion asks `context.deleteAccount(accountId)` before removing identity. Public errors do not disclose existing accounts.

`oauth.js` exports `oauthRoute(request,context)` returning Response or null and `authenticateAgent(request,context)` returning `{accountId,homeId,deviceIds,scopes,grantId}`. Owns metadata, `/oauth/*`, `/mcp`, records prefixed `client:`, `authorization:`, `code:`, `access:`, `refresh:`. Client registration accepts public OAuth clients only, HTTPS redirects (loopback HTTP for local verification only), no wildcard or arbitrary metadata fetching. Bound registrations and per-IP admission. OAuth authorize requires response_type=code, client_id, exact redirect_uri, state, code_challenge_method=S256, code_challenge, resource=origin+'/mcp', supported scopes `display:read content:write settings:write media:write`. GET records authorization intent and redirects same-origin `/home#connect=HANDLE`. `/api/v1/connections/pending` lists session-bound intents. POST `/api/v1/connections/approve` takes `{intentId,homeId,deviceIds,scopes,duration}` with owner browser CSRF. It calls household `grant.create` then returns `{redirectUrl}` to exact client redirect with code/state. No tokens in chat. Token endpoint form-encoded code/PKCE exchange and refresh rotation, resource/client binding, single use and reuse revocation. `/api/v1/connections/revoke` takes `{homeId,grantId}`. MCP tools `screen_list`, `screen_capabilities`, `family_publish`, `revision_status`, `screen_settings`, `media_upload`. Every call rechecks current membership and household grant, not just bearer expiry. JSON Streamable HTTP, POST initialize/notifications/tools; stateless GET/DELETE return appropriate 405. Accepted protocol versions explicit. No OS or account-administration tools. `authenticateAgent` consults home `grant.check`; scopes do not expand at refresh.

`family.js` exports `validateSnapshot(input,now)`, `validateSettings(input)`, `capabilities()` and `sampleSnapshot(now)`. Schema version 1: `{schemaVersion:1,timezone,generatedAt,expiresAt,briefing:{title,text},weather:[{date,label,high,low,condition}],week:[{date,events:[{title,time,person}]}],reminders:[{title,time,person}],kids:[{name,items:[string]}],parents:[{name,items:[string]}],news:[{title,summary}],prompts:[string],nearby:[{title,when}],photos:[mediaId]}`. Optional arrays normalize to empty. All unknown keys, unsafe markup, invalid timezone/date, nonfinite temperatures, excessive TTL/bounds fail. Bounds weather/week 7, events 2/day, reminders4, kids/parents3 each and items3, news2, prompts3, nearby3, photos10. Text max80 title/name/time and max240 paragraph; overall64KiB and TTL <=24h, generatedAt within5minutes of server clock. Settings `{timezone,quietAfterSeconds,nightStart,nightEnd,brightness,orientation,showPhotos}` where quiet interval30..1800, timeHH:MM, brightness10..100, orientation auto/portrait/landscape. No arbitrary URLs.

Household `homeCall` commands:

- `home.get` -> `{id,name,role,members,screens,grants,settings,revision}`.
- `home.update` `{name,settings}`; `home.export`; `home.delete`; `member.invite`, `member.accept`, `member.remove` with account role checks.
- `screen.attach` `{deviceId,name,epoch}`; `screen.detach` `{deviceId,epoch,operationId}`; registry only service principal `{system:true}`. Device settings and content remain home authority.
- `grant.create` `{clientId,label,deviceIds,scopes,expiresAt}` -> `{id,...}`; `grant.check` `{grantId,deviceIds?,scope?}` -> `{...grant}`; `grant.revoke` `{grantId}`.
- `screen.list`, `screen.capabilities`; `family.publish` `{deviceId,snapshot,expectedRevision,idempotencyKey}` -> `{revision,status:'accepted'}`; `revision.status` `{deviceId,revision}` -> `{acceptedAt,deliveredAt,renderedAt,status}`; `screen.settings` `{deviceId,settings}`.
- `device.poll` `{deviceId,epoch}` -> `{snapshot,revision,nonce,settings,homeName,expiresAt}`; `device.ack` `{deviceId,epoch,revision,nonce}` -> `{rendered:true}`. Principal `{deviceId,epoch}` is registry-authenticated, never supplied by public clients.
- `media.upload` `{data,mime}` where data is base64 normalized JPEG/PNG <=96KiB -> `{mediaId}`; `media.get` `{mediaId}` -> `{data,mime}`; `media.delete` `{mediaId}`. Auth owner or explicitly scoped agent, device only home-bound approved photo references. Strict encoded file/dimensions checks; unsafe originals fail closed.

Registry customer routes all `/api/v1/*` POST mutations exact Origin + CSRF:
- GET `/api/v1/homes` -> `{homes:[{id,name,role}]}`; POST `/api/v1/homes` `{name}` -> `{home}`.
- POST `/api/v1/claim` `{code,homeId}` -> `{pending:true,phrase,screenName}`; screen must confirm before ownership.
- POST `/api/v1/screens/reset` `{deviceId,homeId}` -> `{pending:true}`; old transport loses content immediately, device polls only wipe until local erase acknowledgement, then rotates identity and returns unclaimed. Transfer is reset then new physical claim, never automatic copied home content.
- POST `/api/v1/home` `{homeId,command,input}` dispatches only allowlisted customer commands.

Factory-only POST `/factory/v1/tickets` Bearer `FACTORY_CREDENTIAL`, `{serial,hardwareProfile,publicKey}` -> `{ticket,expiresAt,deviceId}`; approved profile `samsung-sm-t580-demo` or explicit `browser-demo`. Public key is P-256 JWK. Device POST `/device/v1/enroll` `{ticket,publicKey,signature}` verifies signature over ticket and consumes once; repeat returns existing enrollment only after same-key proof. Returns `{deviceId,deviceToken}`. Device bearer token stays native, not renderer; browser demo uses sessionStorage explicitly labeled demo preparation.

Device POST `/device/v1/pairing` -> `{code,manualCode,expiresAt,url}`. `code` is a 128-bit QR secret represented as 32 hexadecimal characters; `manualCode` is a separate uniform six-digit string, including leading zeros. Both aliases identify the same device, epoch and two-minute deadline. The phone accepts spaced or grouped manual numbers; the QR secret is not presented as something to type. Existing twelve-character QR codes remain usable until their original expiry. GET `/device/v1/poll` -> `{state:'unclaimed',pairing?}` or `{state:'confirm',phrase,homeName,expiresAt}` or owned family envelope or `{state:'erase',epoch}`. POST `/device/v1/confirm` `{phrase}` -> `{owned:true}`. POST `/device/v1/ack` `{revision,nonce}`. POST `/device/v1/erase` `{}` -> rotated `{deviceToken,state:'unclaimed'}`. Credential epoch changes deny old content and grants; repeated reset remains pending until erase. Native HTTP intercept adds Authorization only to these same-origin paths and private media, never arbitrary requests.

Manual lookup happens only after verified browser identity and owner membership checks. An encrypted durable sliding budget permits five attempts per account and twenty per source IP in ten minutes, plus 120 attempts globally in two minutes. Account and IP maps are each capped at 128 entries, prune expired entries and fail closed on capacity. QR lookup does not consume this smaller manual-code budget. Creation reserves codes transactionally without overwriting active aliases; cleanup checks the originating QR hash before deleting a recycled manual code. Claiming consumes both aliases atomically and still requires deliberate physical confirmation. A short-code match is only a pending request, never authentication, ownership or access to family content. Guessing can still cause pending-request interference, so rate limits and the matching-words check remain necessary.

## Renderer and kiosk

An owned device poll includes `screenName` and `screenIdentifier`. The latter is the uppercased final six characters of the stable household screen ID. It is a readable label, not a pairing secret or authentication credential. The phone and the display show the same label so families can distinguish equally named screens. Owner browser command `screen.rename` takes `{deviceId,name}` and returns `{saved:true,screen:{id,name}}`. Names are trimmed plain text, at most forty characters. Editors, assistants, devices and service principals cannot rename screens. Renaming does not change device identity, settings, family revision, delivery receipts or grants.

`snapshot:null` or a missing snapshot means no family content. The native `SnapshotState` boundary accepts only an actual JSON object as content and rejects other present types. Empty owned state has expiry zero, no private media and no ACK permission. Transitioning from real content to empty clears obsolete private cache once; repeated empty polls must not repeatedly erase or reconnect the renderer. Actual expiry and clock rollback continue to fail closed. The regression fixture uses unmodified, blob-verified Android 8.1 JSON sources, not a JavaScript approximation of Android's null semantics.

The phone uses one labelled, pasteable numeric field with six visual slots for the manual connection code. Leading zeros are preserved. A scanned strong QR remains an explicit confirmation action, never automatic claiming. The display countdown uses the server pairing `expiresAt`. At expiry it hides the old code and QR while requesting a fresh pairing. Existing twelve-character codes remain usable only until their original expiry.

Home-bound source routes accept verified owner browser requests: POST `/api/v1/providers/location` `{homeId}` reads private input and consent; POST `/api/v1/providers/location/save` `{homeId,address,weather,nearby}` saves or removes it. POST `/api/v1/providers/google/weather` and `/api/v1/providers/google/nearby` accept only `{homeId}`. Time zone is derived from the home. Address and consent stay in encrypted home-bound storage. Export includes only this user-owned input and consent after the household's owner-only export proof. Home deletion removes its location record. No full address or coordinates are sent to the shared display.

GET `/device/v1/local` authenticates the current owned device and returns transient city weather and nearby places. Owned polls expose only `localEnabled` flags and `localRevision`, never the address. Provider responses are not family snapshots, are never persisted in offline caches and do not create family revision or render receipts. They require exact Google attribution, a maximum one-hour lifetime and current source consent. Google output is cleared on loss of authority, changed consent, offline state, night mode and expiry. Unsupported third-party attribution fails closed rather than forwarding arbitrary HTML.

Google lookups run outside the registry's global serialized request gate so polling and revocation can proceed while an upstream request waits. Delivery is serialized after fresh ownership, session, home and source-consent checks. The persistent encrypted Google budget caps actual outbound geocoding, weather and places requests at 300 per UTC day, charged before each fetch, including failures. It is an application request cap, not a dollar budget, project quota or protection against a stolen key. Google credentials stay in protected operator storage and Cloudflare secrets. Configuration is limited to the approved existing external Google Cloud project.

Frontend delegate owns `cloud/product-public/` only. Build copies these as `dist/product/`; Worker maps `/home`, `/screen`, `/welcome`, `/privacy` to product HTML and `/product/*` to its files. Local library bundles `/product/webauthn.js` and `/product/qrcode.js` are copied from pinned dependencies. Family sign-in uses SimpleWebAuthnBrowser global methods. Owner phone retains only HttpOnly session. Display renderer reads native-authenticated API, or labeled sessionStorage demo token; no factory key form on customer screen. DOM uses textContent, not untrusted HTML. QR contains expiring claim fragment only. Physical Confirm is the only claim-completion action. Device media fetched privately becomes bounded blob URLs, removed on expiry/reset. Idle, night, stale/offline and expiry apply locally. No private expired data remains visible or cached. Cache encrypted in native; browser demo session cache is synthetic-only. Screens send ACK after next animation frame of successful visible rendering, never after fetch alone.

Android delegate owns `kiosk/` only, reads this protocol. It provides Java Android Home/WebView app (min26), BOOT_COMPLETED, Android Keystore identity, HTTPS-only fixed configured origin, authenticated intercept for device routes, no remote navigation/OS commands, unique installer input (ADB broadcast only debuggable or activity explicit local installer), Wi-Fi repair, protected owner exit and reset. Debug demo signing is not a commercial signing approval. Build, SDK/JDK setup and per-unit provisioning scripts protect secrets outside E: in a per-user NTFS directory. Do not install/wipe a unit that is not present or compatible.

## Verification and release

Each delegate adds tests for its own module and documents commands and known gaps. Parent runs independent full WebAuthn, two-home, QR-possession, OAuth/PKCE, MCP, photo, offline-expiry and reset journeys against real workerd. Secrets never enter sources, assets, screenshots, logs or links. Unit tests do not qualify hardware, real third-party consent, maintained OS, trademarks or commercial licensing.

## Implemented contract additions

The implementation extends the initial fixed contract above:

- MCP also exposes `family_read({deviceId})` and `media_list({})`. Both require `display:read`; they return only approved screen content or owner-selected media metadata. `screen_list` includes each screen's chosen time zone. A published snapshot must use that time zone. Changing it clears old dated content rather than guessing how to convert free-form event times.
- Owner commands `family.current`, `media.list` and `media.get` support non-destructive photo and source sharing. Export reconstructs approved normalized photos, not just storage chunk names. Optional `weatherAttribution` accepts only `Weather data by Open-Meteo`.
- `/api/v1/demo-screen` is a recent-authentication-only browser trial. Its keys are extractable test keys, not Android Keystore. Its device remains bound to its creating account, including after reset; it may not transfer to another account. Normal prepared native units can transfer through reset and fresh physical claim.
- Device `/device/v1/recover/start` accepts `{deviceId,publicKey}` and returns `{challenge,message}`. Verify accepts `{deviceId,challenge,signature}` with raw 64-byte ECDSA base64url over the exact returned origin/unit-bound message. It consumes the nonce and returns the current transport credential. This recovers lost enrollment/reset responses without allowing bearer-only recovery.
- Cross-actor home deletion, membership acceptance and assistant approval use resumable journals. Grant creation is idempotent by private approval operation. A retried approval with identical consent returns the same unexpired callback; it cannot silently change home, screens or permissions.
- Family content and render receipts have server expiry alarms. Device-local expiry is independent of network access. Media removal issues a fresh revision, so a screen does not retain a deleted photo under an unchanged cache key.
- Owned screens poll at roughly 30 seconds with jitter, hidden screens at 60 seconds, and disconnected screens back off. Clock and privacy checks are local. Interactive pairing is faster. Public, family, screen and approved-assistant admission are separate; verified refresh proof uses its approved budget, never a self-reported client ID.
- Consumer consent defaults to 30 days with a shorter option and deliberate stop. Access tokens remain short-lived and refresh rotates; rights are checked again on every use. This is not permanent or universal assistant access.
- `/api/v1/connections/deny` is authenticated and CSRF-protected. It cancels a pending request with a browser/account/session-bound, idempotent denial and returns the registered callback with `error=access_denied`, original `state` and issuer, never a code or token. The active connection page returns to that callback after success; a decline from the ordinary pending list stays home. Same-document pairing and connection links update the current view without automatically claiming or approving anything.

Provider status and callback are owner-authenticated routes. Google callback query keys are narrowly allowlisted and state-bound. Other customer/device routes reject queries. Source selection, sharing and publication are separate explicit actions. When Google credentials or weather terms/configuration are missing, consumer controls report unavailable rather than a simulated connection.

## Display identification and standby

An owned screen shows its ordinary six-character `Screen` label in every display mode. It matches the label in My home and is not a PIN, pairing secret or native serial. Clearing private content must not remove this label.

Daytime standby can show the next approved family update, a selected photo, the monthly calendar, today's consented weather and one nearby place. Google information remains transient, with required attribution and current ownership, consent, visibility, connectivity and expiry checks. A small clock difference cannot extend local retention beyond one hour.

Overnight standby defaults to a dim clock, public date, date-only monthly calendar and ordinary Screen label. The calendar contains no appointments. Home names, room names, photos, reminders, locations and Google results stay hidden, and no Google information is fetched in this default mode.

The physical Show full display button deliberately leaves quiet hours for the current quiet-night session. It waits for a successful authorized poll started after the button press before showing family content or fetching local information. An earlier in-flight response cannot satisfy this requirement. Back to quiet hours clears private family and local information immediately. Morning ends the override. Neither button changes the household schedule.

Display temperatures can use Celsius or Fahrenheit. Input weather values remain canonical Celsius. The owner-only home.temperature command accepts only temperatureUnit and updates that preference without changing any screen's time zone, quiet hours, photo choices, brightness, family content or revision. Owner previews and daytime and standby display temperatures use the same conversion. Unit changes do not require another Google request.
